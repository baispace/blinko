## 粘贴图片内联到正文（飞书式，2026-10-04 15:52）
- **问题**：编辑器粘贴/拖入图片被 `useEditor.ts` handlePaste/handleDrop 拦截 → `editorStore.uploadFiles` 只进 attachments → 渲染时图片固定在正文下方（BlinkoImageGallery/FilesAttachmentRender）。长文笔记想要飞书式：图片插在光标处。
- **实现**：
  - `editorStore.uploadFiles`：非 BLINKO（NOTE/TODO/comment）的**图片**不再进附件（不 push this.files、不进 attachmentsStorage），上传完成后 `vditor.insertMD('![](原始路径)')` 逐张插到光标处，末尾统一触发 onChange（自动保存接手）。BLINKO 闪念保持微博式九宫格（`noteType === NoteType.BLINKO` 分流）。
  - 新增 `app/src/lib/fileUrl.ts`：`getLocalToken`（localStorage blinkoToken）、`toAuthenticatedFileUrl`（内部路径补 ?token=，后端 getTokenFromRequest 支持 query token）、`toContentFileUrl`（s3CdnDomain → 绝对 CDN 地址；从 editorStore 挪来，editorStore 保留 re-export 兼容 AttachmentRender/icons.tsx）、`toRenderableContentUrl`（CDN 重写 + token）。
  - 新增 `Tiptap/contentImage.ts`：`ContentImage = Image.extend({ renderHTML })` 渲染 DOM 时才解析 src；**markdown 序列化仍写原始路径**——不能把 JWT/CDN 域名写进笔记内容（换环境/换登录失效）。节点名保持 `image`，tiptap-markdown 默认 image 序列化不受影响。useEditor 用它替换直连 `Image`。
  - `MarkdownRender/ImageWrapper.tsx`：src 过 `toRenderableContentUrl`，max-h 200→360、object-cover→contain；新增 `p` 组件映射：**只含图片的段落渲染成 `.md-image-block` div**（否则 HeroUI Image 的 div 包裹层嵌在 `<p>` 里，validateDOMNesting 告警+布局隐患）。
  - `coverUrl.ts` 复用 fileUrl helper。tiptap.css `.tiptap img` 加 max-width:100%、max-height 150→320。
- **验证**：笔记视图粘贴 → 编辑器 imgCount=1、src=CDN 绝对地址、naturalWidth=2（真加载）、附件 chip=0；落库 `![](/api/s3file/...原始路径)`；编辑态粘贴走自动保存同样落库；闪念粘贴仍是附件（fileCards=1、无内联 img）；列表卡片/详情页正常渲染、无嵌套告警。测试笔记已删。

## 封面弹窗"点击无反应"修复（2026-10-02 01:40）
- 现象：全屏编辑态点「编辑封面」/「选择图标」无反应（编辑弹窗 dblclick 路径正常）

  CoverPicker/IconPicker 的 HeroUI Modal wrapper 只给了 `z-[9998]` → Modal 渲染在 body 末尾

- 验证：全屏阅读 → 点正文进编辑 → 点编辑封面 → 弹窗置顶可选；选 cover-1 即时落库
  （DB metadata.cover 确认）；IconPicker 同样置顶；测试数据已恢复（note87 恢复 cover-6，测试笔记已删）
- 经验：**本项目凡 fixed 全屏层用 z-[9999]，任何 portal 弹窗/浮层必须 > 9999**；

## 笔记标识体系现状（2026-10-02 15:25 调研）
- **只有两层标识，都无内容级 ID**：
  1. `notes.id` Int 自增（serial）— 内部主键，所有外键（tagsToNote/attachments/noteReference/
     noteHistory/noteInternalShare/comments）都用它；URL `/detail?id=N`；tRPC `notes.detail`
  2. `notes.shareEncryptedUrl` String? — 8 位 `[a-z0-9]`，首次开启分享时 `generateShareId()`
     生成（Math.random，非 crypto），链接 `/share/<串>`；名为 encrypted 实为不可枚举化，
     关闭分享置 null，再开换新串
- **没有**：uuid / nanoid / slug / permalink / 内容哈希 / 跨实例稳定 ID / 版本号（noteHistory.version 只记历史）
- 实测：34 篇笔记 max(id)=87、仅 1 篇有分享串、全库无 uuid/slug 类字段
- 影响面：导入导出/多实例合并会 id 冲突需重映射；无法按内容去重或做同步冲突判定

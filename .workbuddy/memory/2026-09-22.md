## 代码分析：Blinko 本地研发与测试链路

任务：分析在本地如何研发，以及研发/测试修改后的效果验证方式。

### 关键结论（源码级）

1. **单端口一体化架构，非前后端分离**
   - `server/index.ts:316` 仅监听 `PORT = 1111`，`ViteExpress.bind(app, server)` 把 Vite dev server 作为 Express 中间件挂载。
   - `app/package.json` 的 `dev` 脚本为 `cd ../server && bun run dev` — 前端没有独立 dev server。
   - 因此前后端同源同端口，无 CORS / proxy 配置需要维护。

2. **开发模式分支**：`server/index.ts:98-115`
   - `NODE_ENV === 'production'` → root = `../server`，outDir = `public`
   - 否则 → root = `../app`，加载 `app/vite.config.ts`

3. **Tauri 只是套壳**：`app/src-tauri/tauri.conf.json`
   - `beforeDevCommand: bun run dev`、`devUrl: http://localhost:1111`
   - 桌面端加载的是同一个 1111 服务，前端改动同样吃 HMR。

4. **测试框架 = bun:test**（无 jest/vitest 配置），测试位于 `server/__tests__/{unit,integration,e2e}`。

### 发现的问题（待修，尚未改动代码）

- 🔴 **`bun run test` 是空操作**：`turbo.json` 定义了 `test` 任务，但 `app`/`server`/`shared` 三个 package.json 均无 `test` 脚本，turbo 会直接跳过。实际必须 `cd server && bun test`。
- 🟡 **NODE_ENV 未设置会误启用 PWA 插件**：`app/vite.config.ts` 中 `isDev = process.env.NODE_ENV === 'development'`，未设置时 `!isDev` 为 true，绕过了「开发态禁用 PWA」的意图。建议 dev 显式传 `NODE_ENV=development`。
- 🟡 **`.env.tmpl` 数据库端口 5435 与 `docker-compose.yml` 的 5432 不一致**，易配错。
- 🟢 `dotenv turbo run dev` 前缀冗余：根依赖只有 `dotenv` 包（无 dotenv-cli CLI），而 `server` 的 dev 脚本已自带 bun 的 `--env-file ../.env`。
- 🟢 数据库强制 PostgreSQL（`prisma/schema.prisma` provider = "postgres"）；依赖中的 libsql/sqlite3 服务于 RAG 向量存储，不是主库。

### 已落地的工程优化（今天一起改了）

- `.env.tmpl` 删除，拆分为 `.env.local.example`（本机开发）和 `.env.docker.example`（Docker 部署）
- `.env.README.md` 写完整使用说明
- `.gitignore` 改写：`.env.*` 通用忽略 + 三个白名单豁免
- 根 `package.json` 移除 `dotenv` 前缀（命令不存在，已修；server 的 dev 脚本自带 `bun --env-file`）
- 首次启动必须先 `bun run prisma:migrate:deploy` 建表，否则会报 `The table "public.accounts" does not exist`
- 第二次安装时（之前 integrity 失败后部分包残留），`react-syntax-highlighter` 装成空目录、`d3` 完全缺失，导致 vite 报 `Could not resolve "d3"`、`Failed to resolve import "react-syntax-highlighter"`。修复：删 node_modules 重装（2434 个包 8.4 秒，官方源）。**结论：bun install 失败后必须 rm -rf node_modules 重装，不能 retry。**
- **Demo 文件 404**：原 `prisma/seed.ts` 只 `mkdir(".blinko/files")` 不复制 `prisma/seedfiles/` 下的 demo 资源，导致 attachments 表里有 6 条 demo 元数据但磁盘为空，浏览器 404。**已修 seed.ts**：新增 seedfiles 拷贝逻辑，下次新环境跑 `bun run seed` 即可就位。当前直接 `cp prisma/seedfiles/* server/.blinko/files/` 解决。
- **AI 扩写显示 "Unknown error"**：根因是前端 `app/src/store/aiStore.tsx:310` 用 `item.error?.name`（错误类名）而不是 `item.error?.message`（真实报错）来显示，AI SDK provider 报 "Incorrect API key" / "model not found" / "rate limit" 全部被吞。已修：换成 `message ?? name ?? 'ai error'`，并加 `console.error` 留排查线索；catch 兜底也加 `error.data.message` 兼容 tRPC。同时后端 `server/routerTrpc/ai.ts:154` 的 `writing` procedure 加 try 包住 agent 初始化阶段，避免配置错误（如未配置 AI provider）传裸 Error。

打开 http://localhost:1111 即可。

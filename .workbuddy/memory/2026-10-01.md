## P2「操作即落库 + 完成按钮」（未提交，等用户验收）

背景：P0/P1 落地自动保存后，用户问「编辑/详情/弹窗还需不需要保留发布按钮」。

### 结论依据（关键代码事实）
- `autosaveNote` 只发 `{id, content}`，**不落库 attachments / references / type**
- 后端 `note.ts:1057`：`content == null` 时**提前 return**，跳过附件与引用处理
  → 所以即时落库必须带上 content，否则写入无效
- 附件写入是**追加语义**（difference 后只加新的，不删）；引用是**全量替换语义**
  （`_.difference` 双向 diff，传空数组会清空引用）
- 标题/封面/图标走 `NoteCover.persistMetadata` → `upsertNote({metadata})`，失焦即存，与按钮无关

### 关键设计决策
- **两条链**：`autosaveNote` 用 seq 合并（每次击键只发最新，旧版本丢弃）；`silentUpsertNote`
  不合并（离散操作，合并会丢）。分开是因为合并会丢掉附件/引用这类一次性写入
- **reaction 而非 useEffect 依赖**：`store.references` 等在父组件 render 时还没被
  `useEditorInit` 填充，用 deps 会在首次填充时误触发一次空写；reaction 在
  `useEditorInit` 之后注册，基线即真实值
- 打开笔记时 references/type/files 各触发一次 reaction，300ms 合并窗口把它们合成
  一次幂等空写

### 顺带修掉的隐患
`BlinkoEditor` 打开编辑态时会用本地草稿覆盖 `curSelectedNote.content`（旧代码），
自动保存上线后草稿无价值且有害（多端场景会用旧草稿盖掉服务端新内容再自动写回）。
现在自动保存成功即清草稿 → 草稿只在"崩溃/未保存"时残留，语义变正确。

## P3 页宽设置（2026-10-01 深夜完成，未提交）

### 目标与方案
在全屏编辑器 + /detail 页加入类似飞书的页宽切换：默认 / 较宽 / 全宽。

### 文件改动
- 新增 `store/pageWidthStore.ts`：模式 `default | wide | full` + localStorage 持久化 + cycle 切档；
  `default=1000px, wide=1400px, full=undefined`
- 新增 `Common/PageWidthButton/index.tsx`：自定义 SVG 图标（外框=窗口，内块=正文，
  宽度随档位变化）+ HeroUI Tooltip + 单按钮循环
- `FullscreenEditor.tsx`：移除原来的 `viewMode` 宽度映射，改用 `pageWidth.maxWidth`；
  在 PC 顶部工具栏加 PageWidthButton
- `pages/detail/index.tsx`：容器移除 `max-w-[800px]`，改用 `style={{ maxWidth: pageWidth.maxWidth }}`；
  在卡片上方右对齐放 PageWidthButton
- 三语言包：新增 `page-width` / `page-width-default` / `page-width-wide` / `page-width-full`

### 关键踩坑
**MobX 陷阱**：第一次实现用了 `makeAutoObservable(this)`，但 `PageWidthStore extends Store`
（已有父类），MobX 直接抛出 `'makeAutoObservable' can only be used for classes that don't have a superclass`，
导致整站白屏。改用 `makeObservable(this, { mode: observable, maxWidth: computed, setMode: action, cycle: action })`

## 本轮修掉的两个真 bug

1. **✕ 取消后彻底不能再用**：`abortAiWrite()` 只重置 `isWriting`，没重置 `isLoading`；
   而 `useEditor.run` 的并发守卫是 `if (ai.isLoading)` → 取消后下次 `/ai` 永远弹
   "AI 正在生成中"。修：`abortAiWrite()` 里同步 `isLoading = false` + `writeQuestion = ''`。
   （不依赖被 abort 的请求最终 reject 来清标志 —— 若 abort 没传播到 signal 就永久卡死）

2. **取消却弹错误 toast**：abort 会让 `for await` 抛 AbortError → 落进 `writeStream` 的
   catch → 弹 `ai-writing-service-connection-failed`。修：新增私有字段
   `isAbortRequested`，`abortAiWrite()` 置 true、`writeStream` 开头清 false、
   catch 里优先判该标志 → 静默 return + `onSettled()`。用标志位而不是判
   `error.name === 'AbortError'`，因为 tRPC 可能把错误包一层。

## 一个不显然的 PM 细节（重要）

**widget decoration 的位置必须用 textblock 内部位置，不能用 block 边界。**
- `$from.after()` = block 边界（doc 层级），widget 会被放到段落**外面**甚至被丢掉
- `$from.end()` = textblock 内部末尾，PM 一定渲染成行尾的 inline 元素

所以 `currentBlock()` 现在返回 `{ start, end, inlineEnd, text }`，
`inlineEnd: $from.end()` 只给指示条用；insert 位置仍用 `end`（block 边界）。

## 对齐飞书封面方案（比例 2.35:1 + 调整图片位置）

- 文件 ≤10MB（建议 5MB），支持 JPG/JPEG/PNG/GIF
- 交互：悬停标题点「添加封面」→ **自动随机一张**；悬停封面 → 右下角「编辑封面」，
  子项 = 选择图片（图库 60+ / 本地上传 / 随机）/ **调整图片位置** / 移除封面

## 封面上传 500 的排查与修复

**现象**：用户点「本地上传封面」→ 提示 `Request failed with status code 500`。

**根因**：本地 DB 的 `config.objectStorage = "s3"`，但 **s3Region / s3Bucket / accessKey / secret 全空**。
上传走进 `server/lib/files.ts` 的 S3 分支，`new S3Client({ region: undefined })` 被 @smithy 抛错
`Region is missing`，外层 catch 后返回 500 `{error:"Upload failed"}`，前端完全无信息。

**修复分两层**：
1. **本地环境**：把 `config` 表 id=2 的 `objectStorage` 从 `"s3"` 改回 `"local"`（备份在 `/tmp/blinko-config-id2-backup.json`）。
   改完后 curl `/api/file/upload` 200，封面上传成功。
2. **代码防御**：
   - `server/lib/files.ts`：S3 分支进入前显式检查 region/bucket/key/secret，缺任一就抛可读错误
     `Object storage is set to "s3" but ... is/are not configured. Fill them in Settings → Object Storage, or switch back to "local".`
   - `server/routerExpress/file/upload.ts`：500 响应体带 `detail`，不再只返回 `"Upload failed"`。

**次生问题**：本地存储文件 `/api/file/xxx.png` 需要 token，`<img>` 请求不带 `Authorization`，
上传成功后封面显示裂图。修复：新增 `NoteCover/coverUrl.ts` 的 `toAuthenticatedCoverUrl`，
对 `/api/file/` 路径自动拼 `?token=<localStorage.blinkoToken.token>`；后端 `getTokenFromRequest`
已支持 query token，所以能正常访问。编辑态、选择器预览态、卡片列表展示态三处都应用。

**实测结果**：

- 缺 S3 配置时 curl 返回 `{"error":"Upload failed","detail":"Object storage is set to \"s3\" but s3Region, s3Bucket, s3AccessKeyId, s3AccessKeySecret is/are not configured..."}`

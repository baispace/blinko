## Blinko 运行时技术栈确认（用于部署选型，2026-09-26 00:10）
- **构建必须 bun@1.2.8**（packageManager 锁定）：`bun install` → `bunx prisma generate` → `bun run build:web`(turbo→esbuild) → `bun run build:seed`(tsup)
- **运行时是 node:20-alpine，不是 bun**：dockerfile CMD 走 `start.sh` = `npx prisma migrate deploy && node server/seed.js && node server/index.js`
- 服务端代码**无 `Bun.*` 专有 API 调用**（grep 确认），故 node20 可跑 esbuild 产物 dist/index.js
- 仓库自带 `server.start` 脚本用 `cross-env NODE_ENV=production bun --env-file ../.env ../dist/index.js`（用 bun），与 dockerfile 的 node 路线不同，两者皆可
- 运行时原生依赖：sharp@0.34.1 / lightningcss / sqlite3@5.1.7 / @node-rs/crc32（需 gcc/g++/make/python3 现场编译）+ 全局 prisma@5.21.1 + llamaindex/@langchain/community/@libsql/client（--legacy-peer-deps）
- 结论：裸机部署成本极高（等于手工执行 dockerfile），Docker 为实际唯一合理路径；真正的优化点是「构建位置」而非「是否用 Docker」

# 应用内域名分流部署（新版）

1. 将 blog.baispace.cn 解析到服务器并配置有效 HTTPS 证书。
2. 将本目录 Nginx 文件安装到服务器，替换上游和证书路径，执行 nginx -t 后重载。原域名 server 配置保持原样。
3. 后端设置 TRUST_PROXY=1 并重启，确保采信反向代理的 HTTPS 协议。
4. 博客管理 → 站点设置 → 域名与部署，只填写 https://blog.baispace.cn 并保存。已有域名配置可点击「使用此域名作为博客首页」后保存。
5. 等待最多约 30 秒配置缓存刷新，运行站点检查。

不再填写基础路径、API 地址或部署模式。应用自动以根路径服务公开域名，生成 canonical、RSS、站点地图、分享链接；后台仍在原域名。

## 从旧方案切换

必须删除旧 Nginx 的 /blog 重写/路径映射规则。新配置是完整替代，不要叠加旧规则；切换代理和保存域名应在同一维护窗口进行。
旧部署不会因为更新代码自动切换，只有保存域名/显式启用域名入口后才启用新规则。
不要把博客域名填成后台域名；若 Nginx 在容器内，127.0.0.1 指容器自身，改成实际服务名。

## 验证

- / 返回博客首页，文章、专题直接访问和刷新正常。
- /feed.xml、/moments/feed.xml、/sitemap.xml、/robots.txt 正常。
- /blog 跳转 /；/blog-manage 和 /settings 在公开域名返回 404。
- 搜索、读者反馈、阅读统计、图片、二维码和字体正常。
- canonical 与站点地图地址指向新域名根路径，无 /blog 前缀。
- 原域名登录与博客管理正常。

新域名验证通过后，可在「旧公开链接迁移」启用原域名 /blog 链接的永久跳转。
这不会改动后台根路径或 /blog-manage。

DNS 和 HTTPS 由部署平台提供，保存域名不等于它们已经就绪。本次没有修改线上配置。

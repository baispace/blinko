## 引入 HarmonyOS Sans 字体（2026-09-24 01:15）

**两套独立机制（易混淆，务必区分）**：
1. **默认 UI 字体**：`globals.css` 的 `@font-face` + `--font-family`（含 `:lang(zh-CN)`/`:lang(zh-TW)` 分支），
   由 `lib/harmonyFont.ts` 懒加载 CJK 大字体（SC 8MB / TC 4MB），入口挂在 `lib/i18n.ts` 的 `bindHarmonyFontToI18n(i18n)`。
   → 全站默认就是 HarmonyOS Sans，但**不出现在字体下拉里**。
2. **字体切换下拉（FontSwitcher）**：数据来自 DB `fonts` 表（`api.fonts.list.query()`），
   由 `prisma/defaultFonts.ts` 的 `cdnFonts` + `scanLocalFonts`（只扫 `.woff2`）写入。
   → 要让某个字体出现在下拉，必须往 `fonts` 表加一条记录。

**本次改动**（让 HarmonyOS Sans 出现在下拉）：
- `prisma/defaultFonts.ts`：`cdnFonts` 中「Chinese Fonts」分组前新增一条 `HarmonyOS Sans`
  （`name:'HarmonyOS Sans'`, `url:null`, `isLocal:false`, `sortOrder:115`, weights `[400,500,600,700]`）。
  因 `@font-face` 已在 globals.css 声明，`FontManager.loadFont` 走 `url:null` 分支无需额外文件，
  `applyFont` 设置 `--font-family:"HarmonyOS Sans"` 后浏览器直接命中已有 face。
- 手动 upsert 到 DB：`fonts` 表 `updatedAt` 字段**无非空默认值**（Prisma `@updatedAt` 需应用层维护），
  直接 INSERT 会报 `null value in column "updatedAt"`，必须显式带 `createdAt/updatedAt=now()`。

**字体文件**：`app/public/fonts/HarmonyOSSans/`（`HarmonyOS_Sans_Regular.ttf` 146KB 西文 + `_SC_` 8MB 简中 + `_TC_` 4MB 繁中）。

**启动命令**：`bun run dev:backend`（单端口 1111）；bun 已装在 `~/.bun/bin/bun` 但未入 PATH，

## 🚨 localhost 登录报"密码错误"根因（2026-09-24 01:52）
- **现象**：`localhost:1111/signin` 报密码错误，`0.0.0.0:1111/signin` 正常
- **根因（非密码错、非代码逻辑错）**：macOS 上 `localhost` 优先解析到 IPv6 `::1`，而服务
  `app.listen(1111, "0.0.0.0")` 只监听 IPv4，导致浏览器连 `::1:1111` 被系统代理/连接拒绝（`upstream connect failed: Connection refused` → 502），
  前端把请求失败误报为"密码错误"。`0.0.0.0` 是纯 IPv4 地址，直连成功。
- **修复**：`server/index.ts` 两处 `app.listen(PORT, "0.0.0.0")` 改 `"::"`（双栈，同时监听 IPv4+IPv6），
  `lsof` 确认从 `IPv4 *:1111` 变为 `IPv6 *:1111`，`[::1]:1111` 从 502 → 200。bun --watch 自动重启生效。
- **验证方法（可复用）**：`curl -o /dev/null -w "%{http_code}" http://[::1]:1111/signin` 对比 `http://127.0.0.1:1111/signin`；
  `lsof -nP -iTCP:1111 -sTCP:LISTEN` 看监听的是 IPv4 还是 IPv6。

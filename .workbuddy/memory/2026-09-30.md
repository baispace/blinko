## 第十轮：飞书/Notion 式「打开即编辑、免保存」方案评估（咨询，未落地）
用户问：飞书/Notion 打开就能编辑、改完不用保存，怎么实现的，能否迁移到 Blinko。

### 结论：能迁移，但要拆开两件事
- 「不用保存」= **自动保存 + 无模式渲染**，成本低（前端 debounce + 后端轻量 patch）
- 「多人实时协同」= **CRDT/OT**，要重写存储层（Yjs + 持久化），性价比低，**不建议做**

### 现状差距（已核对代码）
- ①无模式：卡片走 `MarkdownRender` 只读，要进 `FullscreenEditor` 点编辑才切 `BlinkoEditor`（两套渲染）→ 需改造
- ②自动保存：**完全没有**。`useEditor.ts:123` 的 `onUpdate` 只回写 MobX + localStorage 草稿，落库必须点发送
- ③版本冲突：无版本号，纯 LWW，多端同编会互相覆盖 → 加 `version` 乐观锁即可
- ④历史：`noteHistory` 有，但**每次内容变更都无条件写一条**，自动保存会让它爆炸

### 关键风险（后端 upsert 太重，必须先改造）
`server/routerTrpc/note.ts:833` 单次 upsert 的副作用：
- L978-1000 内容变就 `noteHistory.create` 全量快照
- L921-936 `handleAddTags` 逐标签 findFirst/create（N 次查库）
- L1084-1089 删除未使用 tag（又一次查库 + deleteMany）
- L1112-1117 配了 `embeddingModelId` 就 `embeddingUpsert`（每次保存重算向量）
- 还有权限查询 / getGlobalConfig / references diff / attachments diff / SendWebhook

### 前端致命坑（自动保存必须一起改）
- `blinkoStore.tsx:245`：`if (content != null) eventBus.emit('editor:clear')`
  → **自动保存带 content 会清空编辑器**（clearMarkdown 清空正文+files）！
  必须改成只有手动发送 / 创建成功才 emit
- 同文件 L185 `console.log("upsertNote", params)` 调试日志残留，自动保存会刷屏
- `upsertNote` 默认 `showToast: true` → 自动保存每次弹「更新成功」

### 建议路径
P0 编辑态自动保存（debounce 800ms + showToast:false + refresh:false + 后端历史/embedding 节流）
P1 无模式：详情/卡片直接用 Tiptap 的 `editor.setEditable()` 切换，不再两套渲染
P2（不做）Yjs 多人协同

## v11 修复：点完成立即同步两份列表内存（用户 01:32 反馈）
- **根因**：`upsertNote.call` 完成后 `updateTicker++` 触发 `refreshData()`，**只 reset `todoList`（isArchived=false），不 reset `doneTodoList`（isArchived=true）**
- **症状**：点完成 → todoList 重 fetch 过滤掉该条 → UI 立即从 todayList 消失；刷新页面 → doneTodoList 重 fetch 包含该条 → `isCompletedToday(updatedAt=now)` 为 true → todayList 合并后重新包含这条
- **修复**：`app/src/components/BlinkoCard/TodoCard.tsx` 的 `toggle` 在调用 `upsertNote.call` 前**同步修改两份 list 的内存数据**：
  - `willArchive=true`：从 todoList 删除 + 加 updated 到 doneList 头部（updatedAt=new Date().toISOString()）
  - `willArchive=false`：从 doneList 删除 + 加 updated 回 todoList 头部
- **结果**：`todayList = todoList ∪ doneList.filter(isCompletedToday)` 立即合并到位，点完即生效，刷新前后行为一致

## 静态资源 CDN（续3）：生产报「未找到 server/public 目录」修复（13:02）
- **现象**：本地 dev 弹窗预期空，但**正式环境也报**「未找到 server/public 目录（请在生产/构建环境执行）」。

- **修复**：`resolveStaticPublicDir` 改为**有界 BFS（深度≤4）**：从 `__dirname`、父级、`process.cwd()`、以及 `/app`、`/app/server`、`/app/server/public`、`/app/dist`、`/app/dist/public`、`/app/app/dist`、`/app/app/dist/public`、`/app/public`、`<cwd>/server/public`、`<cwd>/app/dist...` 等根出发，取**首个含 index.html 且含 assets/ 的真实构建目录**（严格命中），兜底接受仅含 index.html 的目录（loose）。跳过 node_modules/.git/.vite/src 等。
- **收敛上传范围**：新增 `CDN_STATIC_DIRS = ['assets','fonts','icons','locales']`，`listStaticAssets` 与 `uploadStaticAssetsToCdn` 的 walk 在顶层只深入这 4 个目录、跳过顶层杂文件（index.html/favicon 留源站）。原因：① `rewriteCdnRefs` 只改写这 4 类引用，传它们即可加速；② 若解析到的目录恰好是后端 bundle 目录（含 index.js/lute.min.js），不会误传服务端运行时文件。
- **诊断增强**：找不到时错误文案带上 `process.cwd()`，便于下次若仍 miss 直接定位真实路径。
- **提交**：`46aeb384` fix(cdn): 生产环境静态资源目录定位改为 BFS 扫描（2 文件 +105/-8）→ 已推 `origin/main_baispace`，触发 CI。

## 本地环境 "Cannot GET /" 排查（19:25）
- **现象**：本地 `GET /` 返回 Express 默认 404「Cannot GET /」，但 `/health`=200、`/src/*`=404。
- **根因**：端口 1111 被一个**生产模式**进程（`bun run start`，cross-env 强制 NODE_ENV=production）占着——它从 `server/public` 提供静态资源，而本地 dev 没有这个目录（只有部署/构建后才生成），所以 `/` 404。dev 服务端日志显示之前被 SIGHUP 杀掉（终端关闭），残留的生产进程在 1111 上。
- **修复**：`lsof -tiTCP:1111` 找到宿主进程 pid（沙箱内 /proc 看不到但 kill 可杀），`kill -9` 释放端口；再用绝对 bun 路径重启 dev：`cd /Users/baihe/blinko/server && ~/.bun/bin/bun --env-file ../.env --watch index.ts`（注意 app/package.json 的 `dev` 脚本内部用裸 `bun`，沙箱里不在 PATH，必须直接调绝对路径）。重启后 `/`=200、`/src/main.tsx`=200、StorageSetting.tsx 经 Vite 转译为 JS（非白屏 fallback）。
- **结论**：本地跑 CDN 功能应始终用 **dev 模式**（`bun run dev`）；若想本地用生产模式测上传弹窗，需先 `bun run build:web` + `ncp dist/public server/public` 再 `bun run start`，否则 `server/public` 不存在会 404。dev 模式下弹窗显示「未找到 server/public」属预期（无构建产物）。

## 一、产品概览

### 1.1 定位

Ink 是一个**自托管的个人知识与内容工作台**，把四件事合到一个服务里：

| 维度 | 能力 |
|---|---|
| 记录 | 闪念 / 笔记 / 待办 三种轻量到重量的记录形态 |
| 组织 | 多级标签、双向引用、版本历史、附件归集 |
| 智能 | 多厂商大模型接入、RAG 语义检索、AI 工作流、定时任务 |
| 对外 | 公开博客、内容发布、MCP 协议、REST API、OpenAI 兼容接口、插件系统 |

全部数据存放在你自己的 PostgreSQL 与本地文件（或 S3）中，无遥测。

### 1.2 核心概念：三种记录类型

这是理解整个产品最关键的一组区分。类型由数据库 `notes.type` 字段决定（`prisma/schema.prisma:91`）：

| 类型 | 枚举值 | 定位 | 入口 | 侧边栏图标色 |
|---|---|---|---|---|
| **闪念** Blinko | `0` | 灵感速记，一句话 | `/` | 黄 |
| **笔记** Note | `1` | 长文、教程、深度思考 | `/?path=notes` | 蓝 |
| **待办** Todo | `2` | 任务、计划、截止日期 | `/?path=todo` | 绿 |

三者共用同一个编辑器（`app/src/components/BlinkoEditor/index.tsx`），通过 `fixedNoteType` / `composerVariant` 区分形态，**闪念与笔记可通过右键菜单互相转换**，但转换只改 `type` 字段，正文与附件原样保留。

> **注意**：`待办` 的「已完成」不是独立状态，而是 `isArchived = true` 的待办项。侧边栏的「已完成」列表实际过滤的就是 `type=2 AND isArchived=true`（`app/src/store/blinkoStore.tsx:503-518`）。

### 1.3 支持平台

| 平台 | 形态 | 说明 |
|---|---|---|
| Web | 浏览器 | React 18 + Vite + HeroUI，端口 1111 |
| 桌面 | Tauri 2 | macOS / Windows / Linux，含 3 个全局快捷键小窗 |
| 移动 | Tauri 2 | Android 正式，iOS 实验性 |
| 服务端 | Node + Express | 同时提供 Web 静态托管、tRPC、REST、MCP |

前端在启动时会自动分流（`app/src/main.tsx:24-42`）：读到服务端注入的 `window.__INK_BLOG_RUNTIME__` 且命中公开站条件时加载**公开博客应用**（`PublicBlogApp.tsx`），否则加载**工作区应用**（`App.tsx`）。同一个进程因此能同时服务私有工作区与公开站点。

### 1.4 数据存放在哪

| 数据 | 位置 |
|---|---|
| 笔记 / 标签 / 评论 / 用户 / AI 配置 | PostgreSQL（`DATABASE_URL`） |
| 附件原文件 | 本地 `.blinko/files/` 或 S3 兼容对象存储 |
| 向量索引（RAG） | 本地 SQLite `.blinko/vector/embeddings.db` |
| 插件 | `.blinko/plugins/` |
| 数据库备份 | `.blinko/pgdump/` |
| 全局配置 | 数据库 `config` 表（改完即时生效，不必重启） |

## 二、安装与部署

### 2.1 部署方式对照

| 方式 | 适用场景 | 命令 | 难度 |
|---|---|---|---|
| Docker Compose | **生产部署首选** | `docker compose -f docker-compose.prod.yml up -d` | ⭐ |
| Docker 单容器 | 已有独立数据库 | `docker run ...` | ⭐⭐ |
| 本地源码 | 二次开发 | `bun install && bun run dev:backend` | ⭐⭐⭐ |
| Helm / K8s | 集群运维 | `helm install my-blinko ./helm` | ⭐⭐⭐ |
| 桌面端 | 个人本地使用 | Tauri 构建产物 | ⭐⭐ |
| 移动端 | 手机访问 | Tauri Android 构建 | ⭐⭐⭐ |

### 2.2 方式一：Docker Compose（推荐）

```bash
# 1. 获取代码
git clone https://github.com/baispace/blinko.git ink
cd ink

# 2. 准备配置
cp .env.docker.example .env
```

编辑 `.env`：

```bash
NODE_ENV=production

# 容器内 PostgreSQL（compose service name 为主机名）
DATABASE_URL=postgresql://postgres:你的密码@postgres:5432/postgres

# 公网/反代域名（改成你的真实地址）
NEXTAUTH_URL=https://ink.example.com
NEXT_PUBLIC_BASE_URL=https://ink.example.com

# 可选：公开博客的 canonical origin（不配则按请求 Host 推断）
BLOG_PUBLIC_URL=https://blog.example.com
```

```bash
# 3. 启动
docker compose -f docker-compose.prod.yml --env-file .env up -d

# 4. 验证
curl http://localhost:1111/health     # => {"status":"ok"}
```

打开 `http://localhost:1111`，进入 `/signup` 创建第一个账号（**第一个注册的账号自动成为超级管理员**）。

容器启动时 `start.sh` 会自动执行：

1. `prisma migrate deploy` —— **迁移失败即退出**，不带着旧 schema 继续服务（`start.sh:22-33`）。若日志报迁移失败，用 `prisma migrate resolve --rolled-back <失败迁移名>` 修复后重启。
2. `node server/seed.js` —— 注入演示标签、欢迎笔记与内置字体。
3. 静态资源预压缩 —— 生成 `.gz` 直出，减少首屏传输。

> ⚠️ **仓库里的 `docker-compose.prod.yml` 带有本地调试残留**（`DATABASE_URL` 指向 `192.168.31.69:5435`，网络模式为 `host`，PostgreSQL 服务被注释掉）。部署前请按你的实际情况改写这个文件，或直接用上面的 `--env-file` 方式注入变量。

### 2.3 方式二：Docker 单容器

仓库根目录的 `install.sh` 提供了一键脚本：自动创建 `blinko-network` 网络、拉起 `postgres:14` 容器、拉起应用容器，并交互式询问是否挂载本地 `.blinko` 目录。

```bash
chmod +x install.sh && ./install.sh
```

手动等价写法：

```bash
docker network create blinko-network

docker run -d --name blinko-postgres --network blinko-network \
  -e POSTGRES_DB=postgres -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=你的密码 \
  --restart always postgres:14

docker run -d --name blinko-website --network blinko-network \
  -p 1111:1111 \
  -e NODE_ENV=production \
  -e DATABASE_URL=postgresql://postgres:你的密码@blinko-postgres:5432/postgres \
  -v /你的路径/.blinko:/app/.blinko \
  --restart always blinkospace/blinko:latest
```

### 2.4 方式三：本地开发

前置：**Node.js ≥ 20**、**Bun ≥ 1.2.8**、**PostgreSQL ≥ 14**。

```bash
# 1. 安装依赖
bun install

# 2. 准备 PostgreSQL
createdb blinko

# 3. 环境变量
cp .env.local.example .env
# 修改 DATABASE_URL 中的用户名（本机 mac 用户名）

# 4. 建表 + 生成客户端
bun run prisma:migrate:deploy
bun run prisma:generate

# 5. 启动（Express + Vite 合并，端口 1111）
bun run dev:backend
```

也可分前后端启动：

```bash
bun run dev:backend    # 仅后端
bun run dev:frontend   # 仅前端
bun run dev            # Tauri 桌面端
```

**开发期避坑（来自 `.env.README.md`）**：

- `bun install` **必须用官方源** `https://registry.npmjs.org`。用 `registry.npmmirror.com` 会因 tarball 302 后 sha256 不一致而大批 `IntegrityCheckFailed`。
- `bun install` 失败后必须 `rm -rf node_modules` 再装，残留的空目录会让 vite 报 `Could not resolve`。
- `NODE_ENV` 必须为 `development`，否则 `vite.config.ts` 会误启用 PWA 插件。

### 2.5 方式四：桌面端（Tauri）

```bash
# macOS（Apple Silicon）
cd app && bun run tauri:mac:build
# 通用
bun run tauri:desktop:build
```

前置：Rust 工具链 + Tauri 系统依赖（Linux 需 `webkit2gtk` 等）。

桌面端通过 `app/src-tauri/tauri.conf.json` 定义 4 个窗口：

| 窗口 | 尺寸 | 作用 |
|---|---|---|
| `main` | 1920×1080 | 主窗口，关闭时**隐藏到托盘**而非退出 |
| `quicknote` | 600×125 | 全局速记浮窗，内容自适应高度 |
| `quickai` | 600×125 | 全局 AI 提问浮窗 |
| `quicktool` | 190×34 | 文本选中工具条（翻译 / 复制 / 解释 / 收藏） |

**默认全局快捷键**（可在「设置 → 个性化 → 快捷键」修改）：

| 快捷键 | 动作 |
|---|---|
| `Shift + Space` | 唤起速记浮窗 |

### 2.6 方式五：移动端


### 2.7 方式六：Helm / Kubernetes

```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
helm install my-blinko ./helm
```

Chart 位于 `helm/`，包含 Deployment / Service / Ingress / HPA / ServiceAccount / ConfigMap / Secret 模板。数据库与密钥走 Secret，`NEXTAUTH_URL` 等走 ConfigMap，默认镜像 `blinkospace/blinko:latest`。

### 2.8 环境变量参考

| 变量 | 是否必填 | 说明 |
|---|---|---|
| `DATABASE_URL` | ✅ | PostgreSQL 连接串 |
| `NEXTAUTH_URL` | 建议 | 应用对外地址，用于生成规范链接 |
| `NEXT_PUBLIC_BASE_URL` | 建议 | 浏览器可见的对外地址 |
| `JWT_SECRET` | 可选 | **真正的签名密钥**。留空则首次启动自动生成 32 字节随机值并写入数据库 `config` 表（`server/lib/helper.ts:136-162`） |
| `NODE_ENV` | 建议 | `development` / `production` |
| `BLOG_PUBLIC_URL` | 可选 | 公开博客的 canonical origin，用于 canonical / sitemap / RSS / 分享图地址 |
| `TRUST_PROXY` | 可选 | 设为 `1` 时启用 `trust proxy`（反代后必开） |
| `IS_DEMO` | 可选 | 设为真值会进入演示模式 |
| `MINIMAX_API_KEY` | 可选 | MiniMax 内置密钥 |

> **关键澄清**：仓库 README 把 `NEXTAUTH_SECRET` 列为「生产必须」，但**服务端代码并不读取这个变量**——实际读取的是 `JWT_SECRET`，且留空会自动生成并持久化到数据库。多实例部署时若不显式设置 `JWT_SECRET`，各实例会生成不同的密钥，导致令牌互相不认，**必须显式统一**。

### 2.9 初始化与首个账号

1. 打开 `http://localhost:1111/signup` 注册账号。
2. **第一个注册的账号自动成为超级管理员**（`role = superadmin`）。
3. 超级管理员可在「设置 → 系统 → 用户管理」创建其他账号、重置密码、删除用户。
4. 「设置 → 通用 → 基础设置」中可关闭开放注册（`isAllowRegister`），并开启两步验证（2FA）。

### 2.10 备份、升级与回滚

**备份**（数据 = PostgreSQL + `.blinko/` 目录，两者都要）：

```bash
# 数据库
docker exec blinko-postgres pg_dump -U postgres postgres > backup.sql

# 附件、向量、插件
tar -czf blinko-data.tar.gz /你的路径/.blinko/
```

系统还内置了**每日自动备份**任务（`server/jobs/dbjob.ts`），导出 `.bko` 打包文件，可从「设置 → 数据 → 导入导出」恢复。

**升级**：

```bash
# 仓库根目录 update.sh：备份 → 删旧镜像 → 拉新镜像 → 重建容器 → 恢复挂载
chmod +x update.sh && ./update.sh
```

或手动：

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

**回滚**：把镜像 tag 改回旧版本重新 `up -d` 即可。注意数据库迁移**不自动回滚**——跨大版本回退前请先备份数据库。

### 2.11 反向代理与公开博客域名

公开博客与私有工作区可以共用一个服务，通过路径映射区分。推荐的 nginx 配置：

```nginx
server {
  listen 443 ssl http2;
  server_name blog.example.com;

  # 公开页面：根路径映射到应用的 /blog
  location / {
    proxy_pass http://127.0.0.1:1111/blog/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # 站点地图与 robots 固定在根路径
  location = /sitemap.xml { proxy_pass http://127.0.0.1:1111/sitemap.xml; }
  location = /robots.txt  { proxy_pass http://127.0.0.1:1111/robots.txt; }

  # 公开 API 与公开资源
  location /api/trpc/blog.public { proxy_pass http://127.0.0.1:1111; }
  location /assets/      { proxy_pass http://127.0.0.1:1111; }
  location /font-assets/ { proxy_pass http://127.0.0.1:1111; }
  location /icons/       { proxy_pass http://127.0.0.1:1111; }
  location /locales/     { proxy_pass http://127.0.0.1:1111; }
}
```

**要点**：

- **只映射公开页面与公开资源**。不要把 `/` 整体透传，否则登录页、管理接口、私有笔记都会跟着公开。
- `BLOG_PUBLIC_URL` 设为公开域名（不含路径），服务端的 canonical、站点地图、RSS、分享图都以它为准。
- 反代必须让 `/sitemap.xml`、`/robots.txt`、`/blog/*.xml` 到达应用，**不要给公开 HTML/XML 加长期 CDN 缓存**（公开内容使用 `no-store`，撤回后需立即生效）。
- 部署后到「博客后台 → 站点设置 → 站点检查」点「运行检查」，逐项确认 DNS、HTTPS、文章直访、sitemap、RSS、canonical、CORS 均通过。

## 三、接入方式

### 3.1 鉴权：Personal Access Token（PAT）

Ink **不使用 NextAuth**（代码里 `getNextAuthSecret` 只是沿用旧名的函数），实际是 **Passport + JWT**。

| 令牌 | 获取方式 | 有效期 | 载荷 |
|---|---|---|---|
| 会话 JWT | 登录时签发 | 30 天 | `sub / name / role / twoFactorVerified` |
| PAT（API Token） | 登录返回、或「设置 → 基础设置 → Access Token」 | 100 年 | `sub / name / role / permissions` |

**所有接入方式的统一传参**：

```http
Authorization: Bearer <PAT>
```

也支持 `?token=<PAT>` 查询参数（部分 MCP 客户端需要）。**不支持** `X-API-Key` 之类的自定义头。

签名密钥为 `JWT_SECRET`；留空时首次启动自动生成并存入数据库 `config` 表。

低权限令牌（`permissions` 非空）会做**路径子串匹配**校验；权限数组缺失则视为拥有完整权限。

### 3.2 REST API

Ink 把 tRPC 过程自动暴露成 REST，提供 **108 个 `/api/v1/**` 端点**。

| 资源 | 说明 |
|---|---|
| **OpenAPI JSON** | `GET /api/openapi.json` |
| **Swagger UI** | `GET /api-doc`（浏览器直接打开，支持 `persistAuthorization`） |

**分组概览**：

| 前缀 | 端点数 | 覆盖范围 |
|---|---|---|
| `/api/v1/note/*` | 25 | 列表、详情、创建更新、分享、发布、引用、历史版本、批量操作、回收站 |
| `/api/v1/user/*` | 15 | 登录、注册、用户管理、令牌签发与重签、账号绑定 |
| `/api/v1/public/*` | 11 | 服务端版本、OAuth 提供商列表、链接预览、音乐元数据、站点信息、Hub 列表 |
| `/api/v1/comment/*` | 4 | 评论增删改查（**公开接口，无需登录**） |
| `/api/v1/follows/*` | 8 | 关注 / 取关 / 粉丝 / 推荐列表 |
| `/api/v1/font/*` | 7 | 字体列表、二进制数据、上传与删除 |
| `/api/v1/mcp-servers/*` | 10 | 外部 MCP 服务器管理 |
| `/api/v1/tags/*` | 7 | 标签列表、计数、改名、改图标、删除 |
| `/api/v1/ai-tasks/*` | 5 | AI 定时任务 CRUD、启停、立即执行 |
| `/api/v1/config/*` | 5 | 配置读写、插件私有配置、AI 模型配置 |
| `/api/v1/analytics/*` | 3 | 统计快照、日计数、月统计 |
| `/api/v1/notification/*` | 2 | 通知列表与创建 |
| `/api/v1/tasks/*` | 2 | 导入导出任务 |
| `/api/v1/ai/import*` | 2 | 外部 AI 对话导入与查询 |

> **注意**：`ai`（除 import 外）、`attachments`、`blog`、`conversation`、`message`、`plugin` 这几个 router **没有** REST 映射，只能走 `/api/trpc/**` 或 MCP。

**调用示例**：

```bash
# 登录并拿到 PAT
TOKEN=$(curl -s -X POST http://localhost:1111/api/v1/user/login \
  -H "Content-Type: application/json" \
  -d '{"name":"admin","password":"你的密码"}' | jq -r .token)

# 列出笔记
curl -s -X POST http://localhost:1111/api/v1/note/list \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":-1,"size":20,"page":1,"view":"summary"}'

# 创建笔记
curl -s -X POST http://localhost:1111/api/v1/note/upsert \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"content":"来自 API 的内容","type":0}'
```

### 3.3 MCP Server：把 Ink 暴露给 AI 客户端

Ink 内置一个 MCP Server，向外提供 **11 个工具**，任何兼容 MCP 的客户端（Claude Desktop、Cursor、Cline、Chatbox 等）都能直接读写你的笔记库。

**端点**：

| 传输方式 | 端点 | 说明 |
|---|---|---|
| Streamable HTTP（推荐） | `POST /mcp` | 响应头带 `Mcp-Session-Id` |
| SSE（旧版兼容） | `GET /sse` | 配合 `POST /messages?sessionId=...` 回传 |
| Express 挂载点 | `/`（根） | 注意**不是** `/api/mcp` |

**客户端配置**（在「设置 → AI → 工具 → MCP 接入」可一键复制）：

```json
{
  "mcpServers": {
    "blinko": {
      "url": "http://localhost:1111/mcp",
      "headers": {
        "Authorization": "Bearer 你的PAT"
      }
    }
  }
}
```

旧版 SSE 客户端改为 `"url": "http://localhost:1111/sse"`。

**会话安全**：会话与建立时的用户 id + role 绑定，换用户复用同一 session 会返回 403；两种传输之间不能跨用会话（返回 400）。

**11 个工具一览**：

| 工具 | 入参要点 | 作用 |
|---|---|---|
| `searchBlinko` | `searchText / type / isArchived / isRecycle / withFile / withLink / hasTodo / isUseAiQuery / days` | 检索笔记。`isUseAiQuery=true` 切换为 RAG 语义检索 |
| `upsertBlinko` | `content / type(blinko\|note\|todo) / title` | 创建或更新笔记 |
| `updateBlinko` | `id / content / title / isArchived / isTop / isShare / isRecycle` | 按 ID 局部更新 |
| `deleteBlinko` | `ids: number[]` | 批量移入回收站 |
| `createComment` | `content / noteId / guestName` | 给笔记加评论 |
| `webSearch` | `query` | Tavily 联网搜索（需配置 Tavily Key） |
| `webExtra` | `urls: string[]` | 抓取网页正文 |
| `createScheduledTask` | `name / prompt / schedule(cron)` | 新建 AI 定时任务 |
| `listScheduledTasks` | — | 列出定时任务 |
| `deleteScheduledTask` | `taskId` 或 `taskName` | 删除定时任务 |
| `importConversation` | `conversation.externalId / messages[]` | 幂等导入外部 AI 对话 |

> `importConversation` **只在 MCP Server 暴露**，不会出现在 Ink 自己的 AI 对话工具集里。

### 3.4 OpenAI 兼容接口

如果你希望把 Ink 当作一个 OpenAI 服务接进其他工具：

```bash
curl -X POST http://localhost:1111/v1/chat/completions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{"role":"user","content":"总结我今天的笔记"}],
    "stream": true
  }'
```

| 项 | 说明 |
|---|---|
| 路径 | `POST /v1/chat/completions`（**不是** `/api/v1`） |
| 鉴权 | `Authorization: Bearer <PAT>`，缺失返回 401 |
| 请求体 | `{ messages: [{role, content}], stream?: boolean, model?: string }` |
| 响应 | `stream=true` 返回 SSE（`chat.completion.chunk`）；否则返回标准 `chat.completion` |
| RAG | 由服务端是否配置 embedding 模型**自动决定**，请求方不控制 |
| 联网 | 由服务端是否配置 Tavily Key 自动决定 |

**两个必须知道的限制**：

- 请求里的 `model` 字段**只会被原样回显**，实际始终使用后台配置的默认对话模型——靠 `model` 选模型是无效的。
- 响应中的 `usage` 三个 token 数**固定为 `-1`**，不统计实际用量。
- 没有 `/v1/models` 与 `/v1/embeddings` 端点。

### 3.5 导入外部 AI 对话

把 ChatGPT / Claude 等其他工具的完整对话（角色、模型、时间戳、metadata）沉淀到 Ink。

```bash
curl -X POST http://localhost:1111/api/v1/ai/import \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "conversation": {
      "externalId": "conv_abc123",
      "title": "Ink 二次开源设计讨论",
      "source": "chatgpt",
      "createdAt": "2026-10-15T10:00:00Z"
    },
    "messages": [
      { "externalId": "msg_1", "role": "user", "content": "..." },
      { "externalId": "msg_2", "role": "assistant", "content": "...", "model": "gpt-4o" }
    ]
  }'
```

返回 `{ conversationId, conversationCreated, messagesCreated, messagesUpdated, messagesPruned }`。

**幂等性**：`(accountId, externalId)` 唯一约束，重复推送只更新不重复创建。`externalId` 必须由调用方确定性生成。

> ⚠️ **请求体结构与仓库 README 不一致**：真实 schema 要求把 `externalId` / `title` / `source` 放进嵌套的 `conversation` 对象里，README 示例是扁平结构，照抄会 400。

### 4.1 闪念 / 笔记 / 待办

**闪念**

- **创建**：列表顶部输入框直接输入回车；桌面端长按右下角新建按钮 **800ms** 触发录音；`Shift+Space` 唤起速记浮窗。
- **特点**：极简，支持 `#` 标签与 `@` 引用其它笔记。
- **自动归档**：超过 `autoArchivedDays`（默认 30 天）的闪念由后台任务自动归档（`server/jobs/archivejob.ts`）。

**笔记**

- **创建**：切到 `/?path=notes` 后输入，或在闪念卡片右键「转换成笔记」。
- **编辑器**：Tiptap 富文本，停止输入 **800ms** 自动保存；附件 / 引用 / 类型切换等离散操作合并 **300ms** 窗口落库。
- **版本历史**：卡片右键 → 历史版本，可预览、差异对比、恢复到任意版本（`notes.getNoteHistory` / `getNoteVersion`）。
- **全屏阅读**：`/?path=notes` 打开时进入全屏编辑器；支持大纲、文档侧栏、阅读态切换。

**待办**

- **创建**：`/?path=todo` 下的快速添加；也可把普通笔记右键转成待办。
- **字段**：标题、截止日期（`metadata.expireAt`）、优先级（紧急且重要 / 重要 / 紧急 / 普通）、子任务。
- **工作台能力**：多视图切换、6 种排序（开始 / 截止 / 创建 / 更新 / 完成 / 优先级）、5 种分组（状态 / 无日期 / 截止日 / 优先级 / 标签）、条件筛选、搜索。
- **完成**：勾选即归档，进「已完成」列表；支持「推迟 1 天」「从昨天顺延」。
- **键盘流**：全链路键盘勾选 / 排序 / 过滤。

### 4.7 公开博客与内容发布

这是 Ink 相对上游 Blinko 最大的一整块能力。

#### 4.7.1 博客后台（`/blog-manage`）

10 个分区：`站点设置` / `文章` / `专题` / `封面` / `分发` / `资料` / `友链` / `反馈` / `邮件` / `统计`。

#### 4.7.2 发布流程（四步）

```
保存笔记 → 发布检查 → 查看预览与变更 → 确认发布
```

**核心设计：公开内容是快照，绝不 join 活草稿。**

| 环节 | 行为 |
|---|---|
| 保存 | 私有草稿保存，公开版本**不会**自动同步 |
| 检查 | 服务端比对 source / draft / public 三个版本指纹，检测冲突 |
| 预览 | 可切换「待发布」与「当前公开」逐字段对照，标出变化项 |
| 确认 | 校验保存时间、发布状态、版本号与封面；过期必须刷新后重新确认 |

**发布前的硬性拦截**（任一不满足即拒绝）：

1. 笔记在回收站 → 需先恢复
2. 正文为空 → 拒绝（纯图片无文字允许）
3. 正文含带凭据参数的链接 → 拒绝（站内 `/api/file/*` 地址放行并自动剥除凭据）
4. 待发布封面附件已被移除 → 需重新选择
5. 封面类型或大小不符 → 拒绝（需 `image/(png|jpeg|webp|gif|avif)` 且 ≤ 10MB）

**发布后**：

- `notePublication.revision` 版本号 +1（内容无变化则**不**增加）
- 写入一条 `blogPublicationHistory` 历史快照
- 生成 `publishId`（8 位 hex），公开地址为 `/blog/<publishId>`
- 服务端实时渲染首屏 HTML 并注入 canonical / Open Graph / JSON-LD

**撤回与回滚**：撤回只停止公开访问，**快照保留**；重新发布沿用原链接、不重置首次发布时间。

**并发保护**：服务端用 `expectedPublicationToken`（15 项内容的 sha256）+ `expectedUpdatedAt` + 事务行锁，三重校验；前端传来的对比内容不被信任，服务端一律重算。

#### 4.7.3 AI 封面

- **位置**：博客后台 → 封面。
- **模型要求**：必须勾选 `imageGeneration` 能力的模型（OpenAI `images/generations` 或 MiniMax 原生 `image_generation` 协议）。
- **流程**：选模型 → 填方向描述 → 生成底图（1600×900 WebP）→ 选为「待发布封面」→ 调排版 → 发布。
- **关键约束**：**生成只作用于草稿**，公开快照不动，必须「更新发布」后才生效。
- **排版与分享图**：页面文字层是真 DOM，分享图文字层由服务端用 `opentype.js` 读字形轮廓转 SVG 再栅格化，**页面长什么样，分享出去就是什么样**。

#### 4.7.4 专题

- **两种形态**：`专题模式`（卡片式聚合）与 `文档模式`（目录 + 连续阅读）。
- **多级专题**：子专题的文章同时计入父专题的公开列表。
- **章节编排**：专题 → 章节 → 文章三层，章节顺序 → 章内顺序 → 未分章节构成全局阅读顺序。
- **文档模式**可指定「默认打开的文章」。

#### 4.7.5 分发策略

四种模式：`recency`（最新）/ `clicks`（点击）/ `ctr`（点击率）/ `blended`（综合，默认）。

综合模式由 5 个因子加权：新品分、热帖、质量分、亲和度（与访客历史专题相交）、搜索命中。各因子带衰减半衰期（新品 14 天 / 热帖 60 天）。

#### 4.7.6 动态（Moments）

- 动态**不是独立实体**，就是「被公开的闪念」。
- 筛选：全部 / 含图 / 纯文字；按月份分组。
- 支持共鸣与私密反馈；独立 RSS：`/blog/moments/feed.xml`。
- 动态不进文章列表、不进专题。

#### 4.7.7 友链、订阅、反馈、邮件

| 功能 | 说明 |
|---|---|
| 友链 | 读者申请 → 管理员审核 → 进公开列表。邮箱与内部备注**永不公开** |
| 订阅 | 微信二维码 + RSS 两个渠道。**没有邮件订阅名单** |
| 文章表态 | 三种：有启发 / 很实用 / 有共鸣。数量由事实表算出，不存计数器 |
| 私密反馈 | 读者提问 / 补充 / 报错，默认只有作者可见 |
| 邮件通知 | 需配 SMTP。用于友链申请通知、反馈回复通知 |

**邮件配置优先级**：后台配置 > 环境变量（`BLOG_SMTP_HOST/PORT/USER/PASS/FROM/SECURE`）。密码只写不读，回读只有 `hasPass` 布尔值。未配置时如实返回 `not_configured`，不假装发过。

#### 4.7.8 SEO 与站点检查

- **三态对照预览**：草稿 / 当前公开 / 线上真实输出，逐字一致。
- **站点检查**：15 类检查（DNS、首页、文章、专题、404、撤回、API、CORS、资源、canonical、robots、RSS、sitemap、统计、跳转），每项给出通过 / 警告 / 失败 / 需手动验证，并附证据与建议。
- **sitemap**：`/sitemap.xml` 为索引，文章分片每片最多 5000 篇；`lastmod` 取**公开快照**的更新时间，私人编辑不改变公开 lastmod。
- **robots**：公开域名独立时按公开基础路径放行；与工作区同源时只放行 `/blog`，不把工作区放给爬虫。

#### 4.8.4 AI 工作流

8 种，前端把前 3 种做成大卡片：

| 工作流 | 产出 |
|---|---|
| **每日回顾与待办同步** | 结构化草稿 → 落库为日报笔记 |
| **周报与复盘** | Markdown 笔记草稿 |
| **文章练习点评** | Markdown 点评 |
| 提取待办 | JSON 任务列表 |
| 沉淀笔记 | JSON 笔记 |
| 今日优先级 | Markdown 清单 |
| 整理逾期 | Markdown 分析 |
| 整理闪念 | Markdown 归类（**不自动创建**） |

**日报工作流**是其中最重的：读今日记录 → AI 生成变更计划 → 用户确认 → 写回待办 → 生成日报笔记。带并发锁、乐观锁与逐条 SAVEPOINT 回滚；推迟截止日必须填原因；同名待办拒绝重复创建；同一天的日报复用同一篇并写版本历史。

#### 4.8.5 AI 定时任务（`/ai/tasks`）

- **调度**：pg-boss，标准 5 段 cron（UTC）。UI 上暴露「时间 + 频率（每天 / 工作日 / 每周）」三档。
- **执行**：按 prompt 让 AI 做分析，**只读工具集**，不修改不删除用户内容，也不创建新任务。
- **结果**：每任务只保留**最后一次**结果（成功/失败 + 错误信息）；完整历史在 pg-boss 队列里（1 天归档、7 天删除）。
- **内置模板**：「每日事项梳理」（工作日 09:00）、「每周工作复盘」（每周 18:00）。
- **管理**：创建 / 编辑 / 启停 / 删除 / 立即执行；AI 也可通过 MCP 工具自助管理。

#### 4.8.6 AI 后处理（设置 → AI → 行为）

新建或更新笔记后自动执行，模式可选：`生成评论` / `自动打标签` / `智能编辑` / `自定义提示词` / `两者都做`。

## 七、已知限制与注意事项

### 7.1 仓库 README 与实际实现不一致（以本文档为准）

| 项 | README 说法 | 实际实现 |
|---|---|---|
| MCP 端点 | `/api/mcp`、`/api/mcp/sse` | **`/mcp`**、**`/sse`**（MCP router 挂在根路径） |
| AI 对话导入请求体 | 扁平 `{source, externalId, title, messages}` | 需嵌套 **`conversation: {externalId, title, source, ...}`** |
| 「Quick Links」快捷链接 | 最多 12 条可配置 | **该特性不存在**（全仓无匹配） |
| 「工作空间下拉菜单」可自定义 | 可配置内部/外部链接 | 侧边栏菜单**硬编码**，不可配置 |
| 签名密钥 | `NEXTAUTH_SECRET` 生产必填 | 服务端读取的是 **`JWT_SECRET`**，留空自动生成并存库 |
| `deleteBlinko` | 删除（带确认） | 实际直接移入**回收站**，无确认步骤 |
| 编辑器 | Tiptap | ✅ 一致 |

### 7.2 功能性限制

| 项 | 现状 |
|---|---|
| 分享限次访问 | `shareMaxView` 字段存在但**服务端无拦截逻辑** |
| 分享密码 | **明文比较**，未哈希存储 |
| Rerank（重排） | 能力标记与配置项存在，但**服务端无实际调用** |
| `imageGeneration` / `video` 能力 | 仅作标记，未见消费点 |
| Azure 向量 | 标识必须为 `azure`；`azureopenai` 返回空 |
| Anthropic / Gemini 向量 | 无专属分支，落到 OpenAI 兼容分支后实际不可用 |
| OpenAI 兼容接口 `model` 字段 | **只回显，不参与模型选择**；`usage` 恒为 `-1` |
| 低权限令牌权限串 | `genLowPermToken` 写的是 `ai.import`，实际 tRPC 路径是 `aiImport.import`，**该权限项大概率失效** |
| 博客 RSS / 搜索 | 只检索**当前博客所属作者**的已发布快照 |
| 撤回后的外部副本 | 第三方搜索引擎或订阅阅读器已保存的副本**无法由本站删除** |
| 匿名访客识别 | 匿名 ID 不等于真实自然人，换设备/清缓存即成为新访客 |
| 邮件订阅 | **没有订阅者名单**，只有微信二维码 + RSS |

### 7.3 运维注意事项

- **多实例部署必须显式设置 `JWT_SECRET`**，否则各实例密钥不同，令牌互相不认。
- **迁移失败即容器退出**，这是刻意设计。修复用 `prisma migrate resolve --rolled-back <迁移名>`。
- **反代后必须设 `TRUST_PROXY=1`**，否则取到的客户端 IP 不对。
- **不要给公开 HTML/XML 加长期 CDN 缓存**——公开内容用 `no-store`，撤回需立即生效。
- **博客站点检查结果不等于「服务商已收数」**——脚本加载、事件发送、服务商报表是三件事。
- **`aiImport.ts` 含 NUL 字节**，`file` 识别为二进制，普通 `grep` 会整文件漏掉，检索时需 `tr -d '\000'`。
